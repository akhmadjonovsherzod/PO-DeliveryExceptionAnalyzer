# Purchase Order & Delivery Exception Analyzer

An Excel-based analytics tool that reconciles purchase orders, goods receipts, and invoices to flag data quality issues and procurement exceptions. Built to demonstrate the kind of three-way match testing used in audit engagements and the delivery exception monitoring used in supply chain operations.

## Overview

The project simulates a procure-to-pay cycle: a company places purchase orders, receives goods, and gets invoiced by vendors. In any real dataset of this kind, a percentage of records will contain errors, missing approvals, mismatched quantities, late deliveries, or billing irregularities. This project generates a realistic synthetic dataset with these issues deliberately embedded, then builds a repeatable process in Excel to detect them.

## Dataset

Three linked tables, joined on `PO Number`:

- **Purchase Orders** (700 records) — order date, vendor, quantity, unit price, approver, promised delivery date
- **Goods Receipts** — quantity and date actually received; a subset of purchase orders have no matching receipt
- **Invoices** — quantity and price billed by the vendor; a subset of purchase orders have duplicate invoices

Irregularities are injected at fixed rates during generation, including missing approvals, missing goods receipts, quantity mismatches between orders and receipts, price variances between orders and invoices, late deliveries, and duplicate billing.

## Methodology

**1. Data generation**
A Python script builds the three source tables with controlled randomness, so the irregularity rates are known in advance and can be used to validate each later step.

**2. Extract, transform, load**
The three CSV files are imported into Excel via Power Query, cleaned (correct data types, trimmed text fields), and merged into a single reconciled table using left outer joins on `PO Number`. This preserves purchase orders with no matching receipt or invoice, which is itself a key signal.

**3. Data quality checks**
Formula-based checks flag structural issues in the merged data: missing approvals, missing goods receipts, missing invoices, invalid dates, and duplicate purchase order numbers.

**4. Exception testing**
A second layer of checks applies business logic on top of the clean data:

- Quantity variance between purchase order and goods receipt
- Price variance between purchase order and invoice, using a materiality tolerance rather than an exact match, to avoid flagging trivial rounding differences
- Late delivery, comparing actual receipt date against promised delivery date
- Duplicate invoicing, identifying purchase orders billed more than once

**5. Reporting**
Results are summarized in a PivotTable-based dashboard, with exception counts broken down by vendor, supporting both an audit review use case and a delivery performance monitoring use case.

## Key Results

On the current dataset (700 purchase orders, 726 reconciled records after accounting for duplicate invoices):

| Check | Count |
|---|---|
| Missing approval | 39 |
| Missing goods receipt | 58 |
| Missing invoice | 0 |
| Invalid dates | 0 |
| Duplicate purchase orders | 0 |
